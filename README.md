## 工具 1：wu138di X GIF下载器 v1.0

相信大家在 X 上刷着刷着，肯定有过这样的疑惑：为什么图片可以直接复制、下载，GIF 动图却没那么方便？

不少看起来是 GIF 的动图，实际上是 X 提供的循环 MP4 视频。所以我写了这款小工具：读取帖子里的媒体链接，保留原始 MP4，再转换成 GIF，方便大家保存和使用。

配图与程序展示：[前往 X 查看](https://x.com/wudihao138hack)。（爱 Miku！）

### 一：使用教程

#### 1. 粘贴帖子链接，确认预览

下载发布包，解压后打开 **wu138di X GIF下载器 v1.0.exe**，将带有图片、视频或动图的 X 帖子网址粘贴进链接框。

右侧会自动生成预览，动图会循环播放；一条帖子里有多项媒体时，可以通过预览区的左右箭头切换。下载列表也会显示对应缩略图，点击条目即可切换右侧大预览。确认无误后，点击 **下载**。

[参考帖：Gangban「大家早上好！又是一天周一，今天也继续努力吧😋……」](https://x.com/798145343h/status/2114550605356122308/photo/2)

默认保存到 Windows 当前用户的“下载”文件夹下的 **wu138di X GIF下载器** 文件夹，通常位于 C 盘。点击 **更改** 即可自行选择保存位置。

#### 2. 等待转换，查看保存结果

下载 GIF 动图时，中间会有一个转换过程，耐心等待即可。默认会保存两份文件：

- **MP4**：直接保存平台提供的原始视频，不重新压缩。
- **GIF**：转换后的循环动图，方便作为图片使用。

看到 **下载完成** 后，点击 **打开保存文件夹** 即可查看。

下载完成界面与文件示例：[前往 X 查看](https://x.com/wudihao138hack)。

右上角的选项按钮可以切换 **跟随链接 / 全部媒体**，也可以关闭 **另存 GIF**。

### 二：下载与运行

- [前往 Release 下载](https://github.com/wu138di/wu138di_tools/releases/tag/x-gif-v1.0)
- 支持 Windows 10 / 11 x64。
- 可直接下载 EXE，也可下载 ZIP 发布包后解压运行。
- 已内置 Python 和 FFmpeg，无需另行配置；系统需有 Microsoft Edge WebView2 Runtime。
- 仅支持公开可访问的 X / Twitter 帖子；网络、帖子权限或平台接口变化可能影响获取。
- GIF 有 256 色限制，文件通常也比 MP4 大；需要保留平台源画质时，使用同时保存的 MP4。

## 工具 2：wu138di通用UE资产提取器 v1.0（usmap版）

相信大家每次玩游戏的时候，总想提取插图 or 立绘，但是不知道怎么办才好……UE 游戏里的素材大多躺在 Paks 里，FModel 这类查看器得先拿到游戏的映射文件（`.usmap`），才能把类结构和属性名正确读出来。

所以我写了这个一键生成映射的小工具：选择游戏目录，它会自动找到游戏主程序、识别引擎版本，读取游戏进程生成 `游戏名.usmap`，再交给 FModel 使用。整个过程只读取游戏进程，不注入 DLL，也不改动游戏本体。（已适配最新的寂静岭 Townfall）

### 一：使用教程

#### 1. 选择游戏目录

打开 **wu138di通用UE资产提取器 v1.0(usmap版).exe**，选择游戏根目录。Steam 安装和普通安装都可以，工具会自己找出主程序，跳过附赠程序和多项目目录。

#### 2. 耐心等待提取完成

如果游戏没有在运行，工具会通过 Steam 安装记录或本地启动器把它拉起来，读取完成后再把自己启动的游戏正常关闭；你原本开着的游戏不会被关闭。

版本一般会自动识别，实在认不出来时会弹出版本选择框，请按游戏的真实版本选择——选错版本一样能生成文件，但在 FModel 里会解析出错。

#### 3. 导入 FModel 使用

提取成功后，游戏根目录会出现 `游戏名.usmap`。在 FModel 中加载这个映射文件，再选择游戏的 Paks 目录，就可以浏览、导出资产了。

如果提取失败或出现错误，把游戏目录下 `_usmap_export/oneclick.log` 里的错误日志发给我，或直接联系我处理。

### 二：已知情况与限制

- 支持 Windows x64 的 UE4 / UE5 游戏，版本覆盖 UE4 4.0—4.27、UE5 5.0—5.8。
- 目前实测通过的游戏：DontLie（UE5.4）、寂静岭 Townfall（实际 UE 5.6.1）。
- “可选版本”不等于“每款游戏都已验证兼容”，特殊编译配置或读取受限的游戏可能还需要单独适配。
- 只读取游戏进程，不注入 DLL、不改动原程序；已有映射会先备份为 `游戏名.usmap.bak`，校验通过后才替换。
- 映射文件会经过结构、名称引用、枚举、类 / 属性及核心引擎类检查，但这不等于每个资产都能在 FModel 里逐项解析成功。
- 工具库与日志留在游戏目录的 `_usmap_export/` 下，不写入系统目录。
